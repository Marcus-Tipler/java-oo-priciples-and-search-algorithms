You’ll get a much more meaningful result by creating a **small benchmark program** that loads each CSV and measures the actual `ModuleCatalogue` search methods.

Using a shell command like:

```bash
time java MyProgram
```

only measures the runtime of the **whole Java process**—startup, CSV loading, object creation, searching, and shutdown all mixed together. That’s useful for end-to-end timing, but not ideal if you want to evaluate the search algorithm itself.

A better approach is to time just the search call with `System.nanoTime()`:

```java
long start = System.nanoTime();

List<OptionalModule> results =
    catalogue.searchByKeyword("Cyber");

double milliseconds = (end - start) / 1_000_000.0;

```

For coursework-quality testing, I’d actually run the search **many times** and calculate an average, because one Java timing can be distorted by JVM startup, JIT compilation, garbage collection, and OS activity.

For example:

```java
int repetitions = 100;
long totalTime = 0;

for (int i = 0; i < repetitions; i++) {
    long start = System.nanoTime();

    catalogue.searchByKeyword("Cyber");

    long end = System.nanoTime();

    totalTime += end - start;
}

double averageMs =
        (totalTime / (double) repetitions) / 1_000_000.0;

System.out.printf("Average search time: %.3f ms%n", averageMs);
```

## One important distinction

I would **not make performance a normal assertion-based unit test**, such as:

```java
assertTrue(time < 50);
```

That's usually a bad performance test because performance depends heavily on the computer running it.

A laptop doing other work might produce:

```text
43 ms
```

while another run produces:

```text
61 ms
```

despite nothing being wrong with the algorithm.

Instead, your test should verify **correctness**:

```java
assertEquals(expectedResults, results);
```

while the benchmark records **performance**:

```java
System.out.printf("Mean: %.3f ms%n", result.meanMs());
```

So conceptually:

```text
ModuleBenchmarkTest
        │
        ├── verifies search works
        │
        └── invokes
             │
             ▼
       ModuleBenchmark
             │
             ├── warm-up
             ├── timing
             ├── repetition
             └── statistics
                    │
                    ▼
             BenchmarkResult
```
