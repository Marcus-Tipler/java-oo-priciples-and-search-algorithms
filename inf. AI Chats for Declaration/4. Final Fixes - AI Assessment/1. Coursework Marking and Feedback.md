## The bigger data-structure problem

Even your new binary implementation still stores:

```java
private final List<OptionalModule> modules;
```

and constructs:

```java
this.modules = new ArrayList<>(modules);
```

So you haven't really **replaced the inefficient data structure**. You've changed the search algorithm applied to an `ArrayList`.

For exact module-code lookup, a more obvious data-structure choice would be:

```java
Map<String, OptionalModule>
```

which gives expected:

```text
construction: O(n)
lookup:       O(1) average
space:        O(n)
```

rather than:

```text
sorting: O(n log n)
lookup:  O(log n)
space:   O(n)
```

Binary search is certainly much better than linear search, but it is difficult to justify it as the **most appropriate data structure/algorithm combination** for exact keyed lookup.

That matters particularly because Learning Outcome 6 says you need to:

> identify the most appropriate data structure and algorithm.
